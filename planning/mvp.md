# RLMask MVP 설계

> 피치용 데모. 도메인은 **미국 병원(임상) 데이터**.

## 목표

병원 환자 데이터를 넣으면 개인정보가 **일관성 있는 가상 페르소나**로 바뀌고, 진료 맥락은 그대로 남는 것을 화면에서 보여줍니다.

- 같은 환자는 환자 테이블과 진료 기록 어디에서나 **같은 가상 인물**로 바뀝니다.
- 진단 코드, 처방, 경과, 날짜 간격 같은 **학습에 필요한 정보는 유지**합니다.
- 결과물에 원본 개인정보가 남지 않았는지 **검증 결과를 수치로** 보여줍니다.

## 실제 제품(A안)과 MVP의 차이

실제 제품은 고객 망 안에 설치하는 **온프렘 + 로컬 LLM** 구조입니다(`subject.md`). MVP는 빨리 보여주기 위해 두 부분만 임시로 바꿉니다.

| A안 실제 제품 | MVP 대체 | 나중에 교체할 지점 |
|---|---|---|
| 고객사 DB (READ only) | 브라우저 **localStorage** | `DataSource` 인터페이스 → DB 커넥터 |
| 로컬 LLM (vLLM, 고객 GPU) | **Anthropic API** (Next.js 서버 라우트에서 호출) | `PiiDetector` 인터페이스 → 로컬 모델 |
| 설치형 패키지 | `pnpm dev` 로컬 실행 | 오프라인 설치 번들 |

페르소나 매핑, 비식별화 정책, 검증, 어드민 UI는 A안에서도 그대로 씁니다. 교체 지점 두 곳만 인터페이스로 분리해 둡니다.

> **데모 설명:** "MVP에서는 LLM만 API로 대체했습니다. 실제 제품은 같은 파이프라인을 고객 망 안의 로컬 LLM으로 돌립니다."

## 데이터 입력

### 1. 정적 샘플 데이터 (기본)

`public/samples/hospital/` 에 합성 데이터 CSV 두 개를 둡니다. 모두 가상 데이터입니다.

| 파일 | 행 수 | 내용 |
|---|---|---|
| `patients.csv` | 15 | 환자 기본 정보: MRN, 이름, 성별, 생년월일, SSN, 전화, 이메일, 주소, 보험 ID, 주치의 |
| `clinical_notes.csv` | 22 | 진료 기록: 환자 ID, 진료일, 진료과, ICD-10 코드, 작성 의사, **자유 텍스트 메모** |

합성 데이터임을 분명히 하는 규칙:
- SSN은 `900-` 으로 시작합니다. 실제 SSN에 발급되지 않는 번호대입니다.
- 전화번호는 `555-010x` 대역(가상 번호), 이메일은 `example.com/.org/.edu` 도메인입니다.

데모에서 보여줄 장면이 샘플 안에 미리 들어 있습니다.

| 장면 | 샘플 위치 |
|---|---|
| 같은 환자가 여러 메모에 등장 → 같은 페르소나로 일관되게 치환 | P001(N001·N002), P002, P003, P004, P005, P006, P012 |
| 호칭 변형 (Mrs. Whitaker, Ms. Ramirez, 이름만 "Marcus") | N001, N002, N010, N020 |
| 가족·지인 이름과 연락처 (환자 테이블에 없음 → LLM이 찾아야 함) | Karen Whitaker, Ngozi Okafor, Peter Jensen 등 |
| 테이블과 다른 이메일 변형 | N013 `aisha.r@example.com` |
| 메모 안의 MRN | N003, N007 |
| 직장·학교·시설 이름 | Okafor Roofing, Westbrook University, Maple Grove Senior Living |
| 89세 초과 환자 (HIPAA 나이 집계 규칙) | P004 Harold Jensen, 91세 |
| 미성년 환자와 보호자 | P015 Olivia Brennan, 15세 |
| 메모 안의 나이가 생년월일과 일치 | 모든 "NN-year-old", "NNM/F" 표기 |

### 1-1. 멀티모달 샘플 (텍스트 · 이미지 · 오디오)

`encounter_media.csv` 한 행에 텍스트, 이미지, 오디오가 컬럼으로 함께 들어 있습니다. 이미지·오디오 컬럼에는 파일 경로가 들어가고, 파일은 `media/` 아래에 있습니다. 6건 모두 `patients.csv`의 환자와 연결됩니다.

| `audio_transcript` | 텍스트 (정답) | 오디오 원문. 화자가 둘 이상이면 `화자: 발화` 형식 |

|---|---|---|---|

| M002 | P002 Daniel Okafor | 보험 카드 | 배우자 음성메시지 |
| M003 | P004 Harold Jensen (91세) | 환자 팔찌 (바코드 포함) | 간호사 ↔ 아들 통화 |
| M004 | P006 Marcus Bell | 심전도 출력지 (ST 하강) | 응급실 의사 구술 |

| M006 | P015 Olivia Brennan (15세) | 학교 투약 동의서 | 의사 ↔ 보호자 통화 |

- **정답지:** `encounter_media_answer_key.json` 에 레코드별로 이미지·오디오 안에 들어 있는 개인정보 값 목록이 있습니다. 검증 단계에서 "놓친 PII"를 계산하는 데 씁니다.
- **생성 방법:** 공개 데이터셋 중 세 모달리티가 같은 환자로 묶이고 PII까지 들어 있는 것은 찾지 못해 직접 생성했습니다. 이미지는 Pillow로 그리고, 오디오는 macOS 내장 TTS(`say`)로 합성했습니다. 얼굴 사진은 오프라인으로 생성할 방법이 없어 넣지 않았습니다.

검토했던 공개 데이터셋:
- **PriMock57** (CC BY 4.0): 실제 사람 목소리의 모의 진료 녹음 57건. 하지만 이름·생년월일 같은 신원 확인 대화가 거의 없어 PII 마스킹 데모에는 맞지 않습니다.
- **MIDI** (TCIA 기반 DICOM): 헤더와 픽셀에 합성 PHI를 넣은 영상 de-id 벤치마크. 영상(DICOM) 비식별화로 확장할 때 후보입니다.

### 2. CSV 업로드

사용자가 직접 CSV를 올려 같은 파이프라인을 돌릴 수 있습니다.

- **컬럼 역할 자동 추정:** 헤더 이름과 값의 패턴으로 컬럼마다 역할을 추정하고(이름, 생년월일, SSN, 전화, 이메일, 주소, ID, 자유 텍스트, 유지), 사용자가 정책 화면에서 확정합니다.
- **사람 키 지정:** 어떤 컬럼이 "같은 사람"을 나타내는지(예: `patient_id`) 지정합니다. 이 키로 테이블 간 일관성을 맞춥니다.
- **여러 파일 연결:** 두 파일이 같은 사람 키 컬럼을 가지면 하나의 데이터셋으로 묶습니다. 샘플(`patients` + `clinical_notes`)과 같은 구조입니다.
- 샘플 CSV는 다운로드할 수 있게 해서 **업로드 양식 예시**로도 씁니다.

**업로드 안전장치 (MVP는 LLM을 외부 API로 대체했기 때문에 필요):**
- 업로드 화면에 경고 배너: "자유 텍스트 컬럼은 Anthropic API로 전송됩니다. 합성 데이터나 외부 전송이 허가된 데이터만 올리세요."
- 업로드 전 확인 체크박스가 필수입니다.
- 크기 제한: 파일당 1MB, 합계 1,000행 내외(localStorage 약 5MB 한도 고려).

## 처리 흐름

**메인은 이미지(OCR) 레인입니다.** 정형·텍스트·음성 레인은 목업으로 두고 외부 API를 부르지 않습니다.

```
CSV(샘플 or 업로드)
  → 원본 읽기 → 스키마 스캔 → 페르소나 매핑
  → ┬─ [메인] 식별 에이전트: OCR(tesseract.js) → OCR 텍스트를 Claude로 → PII 글자 영역을 빈칸으로 표시
    │         → 생성 에이전트: 빈칸을 매핑표의 페르소나 값으로 채움 (배경색·글자색 맞춤)
    ├─ [목업] 정형 데이터 마스킹: 규칙 기반 치환
    ├─ [목업] 텍스트 PII 탐지: 규칙 기반 탐지기 (알려진 이름·전화·이메일·날짜·MRN)
    └─ [목업] 음성 인식: 전사문 컬럼 + 규칙 기반 탐지기
  → 개인정보 & 유용성 검증 → 반출
```

- **식별 에이전트 카드**를 누르면 OCR 대상 이미지 목록이 나오고, 이미지를 고르면 인식한 PII가 빈칸(유형 라벨 포함)으로 표시됩니다. 모든 OCR 단어 영역도 켜서 볼 수 있습니다.
- **생성 에이전트 카드**를 누르면 같은 목록에서 이미지별로 치환된 결과, 원본과의 비교, 원본 → 페르소나 값 대응표를 볼 수 있습니다.
- 이미지는 픽셀을 저장하지 않습니다. 영역 좌표, 배경·글자색, 치환값만 저장하고 화면에서 원본 위에 다시 그립니다 (로컬 저장 용량 2.7MB → 약 0.2MB).
- 목업 탐지기는 가족 이름·주소·장소를 놓치므로, 텍스트 레인에서 누출 검사 경고가 나오는 것이 정상입니다.

### 모달리티별 처리 (MVP)

| 모달리티 | 찾기 | 바꾸기 |
|---|---|---|
| 텍스트 | Claude가 PII 위치·종류 반환 | 매핑표로 페르소나 값 치환 |
| 이미지 | OCR로 글자와 좌표를 뽑고, Claude가 어떤 글자가 PII인지 분류 | 해당 영역을 가리고 페르소나 값을 같은 위치에 다시 그림 |
| 오디오 | 음성 인식(STT)으로 단어별 타임스탬프가 붙은 전사문 생성 → 텍스트와 같은 방식으로 PII 탐지 | 해당 구간을 비프음 처리하거나, 페르소나 값을 TTS로 합성해 끼워 넣음 |

- **이미지:** Claude는 이미지 속 글자를 읽을 수 있지만 픽셀 좌표를 정확히 주지는 않으므로, 가릴 위치는 OCR에서 가져옵니다.
- **오디오:** Anthropic API는 오디오 입력을 받지 않습니다. 그래서 STT 단계가 따로 필요합니다(로컬 Whisper 등). A안에서도 로컬에서 돌리는 구성이라 그대로 가져갈 수 있습니다.
- MVP 첫 단계에서는 이미지·오디오의 OCR·STT 결과 대신 정답지와 `audio_transcript`를 써서 흐름부터 보여주고, OCR·STT는 다음 단계에 붙이는 방법도 있습니다.

**LLM의 역할은 "찾기"까지입니다.** Claude는 메모에서 PII 위치와 종류, 그리고 누구를 가리키는지(환자 본인 / 가족 / 의료진 / 기관 등)만 돌려줍니다. 실제 치환은 결정적인 코드가 매핑표로 합니다. 그래서 같은 입력이면 항상 같은 결과가 나오고, 같은 사람은 어디서든 같은 페르소나가 됩니다. 로컬 LLM으로 바꿔도 이 구조는 그대로입니다.

## 비식별화 정책 (기본값)

HIPAA Safe Harbor의 18개 식별자를 체크리스트로 삼습니다.

| 항목 | 처리 |
|---|---|
| 환자 이름 | 페르소나 이름 (성별 유지) |
| 가족 이름 | 별도 페르소나. 같은 성(姓)을 쓰는 가족이면 환자 페르소나의 성을 따름 |
| 생년월일 · 진료일 · 메모 속 날짜 | **환자별 고정 오프셋으로 이동** (날짜 간 간격 보존) |
| 나이 | 유지. 89세 초과는 `90+` 로 집계 |
| SSN | 형식은 같은 가짜 번호 (`900-` 대역) |
| MRN · 보험 ID | 일관된 토큰 (같은 원본 → 같은 토큰). 보험사 접두어(BCX, MCR 등)는 유지 |
| 전화 · 이메일 | 페르소나 연락처 (`555-01xx`, `example.*`) |
| 주소 | 주(state)는 유지. 거리·도시는 페르소나 값, ZIP은 앞 3자리 유지 |
| 직장 · 학교 · 시설 | 같은 종류의 가상 기관명 |
| 의료진 이름 | 기본은 가상 의료진으로 치환 (옵션으로 유지 가능) |
| 성별 · 진료과 · ICD-10 · 처방 · 수치 | 유지 |

## 페르소나

- **MVP:** 내장된 이름·거리·도시 목록에서 시드 기반으로 생성합니다. 같은 사람 키는 항상 같은 페르소나를 받고, 매핑표는 localStorage에 저장합니다.
- **나중에:** 빌드 타임에 Claude로 대량 생성한 페르소나 풀로 교체합니다.

## 검증

- **원본 값 잔존 검사:** 정형 컬럼의 원본 값과 LLM이 찾은 값이 결과물에 그대로 남았는지 문자열로 검사합니다.
- **패턴 검사:** SSN, 전화, 이메일, MRN 형식이 페르소나 값이 아닌데 남아 있는지 검사합니다.
- **리포트:** 항목별 치환 건수, 잔존 의심 건수, 처리 시간을 보여줍니다.

### 유용성 측정 (Utility)

비식별화는 "안 새는 것"과 "여전히 쓸모 있는 것"을 둘 다 증명해야 합니다. 이름·연락처·ID는 바뀌어도 되지만, 아래 값은 원본과 같아야 합니다. 같은 측정을 원본과 결과에 각각 돌려 비교하고, 실행 결과의 **Privacy & utility** 탭과 상단 요약 카드에 표시합니다.

| 묶음 | 측정 | 통과 기준 |
|---|---|---|
| 시간 | 환자별 방문 간격(일) | 100% 동일 |
| 시간 | 방문 시점의 나이 | 99% 이상 동일 |
| 시간 | 날짜 이동 폭 | ±31일 이내 (계절·연도 유지) |
| 연결성 | 테이블 간 환자 대응 | 1:1 (나뉨·합쳐짐 0) |
| 연결성 | 표의 MRN과 메모·이미지 속 MRN | 100% 일치 |
| 연결성 | 같은 이름 → 같은 페르소나, 다른 사람 → 다른 페르소나 | 불일치·공유 0 |
| 분포 | 성별 | 동일 |
| 분포 | 연령대(10년 단위) | 총변동거리 ≤ 0.1 |
| 분포 | ZIP 앞 3자리 지역 | 100% 동일 |
| 분포 | 진단코드·진료과 등 유지 컬럼 | 100% 동일 |
| 분석 결과 동일성 | 30일 내 재방문율, 평균 방문 간격, 평균 나이, 환자당 방문 수 | 동일 (나이는 ±0.5세) |

참고 지표로 "자유 텍스트 중 바뀌지 않은 비율"과 환자별 방문 타임라인(원본 vs 결과)도 보여줍니다. 샘플 기준 14/14 통과, 자유 텍스트의 72%가 그대로 유지됩니다.

## LLM 호출 (MVP)

- Next.js Route Handler `/api/detect-pii` 에서 서버 측으로만 호출합니다. API 키는 `.env.local` 의 `MASKING_ANTHROPIC_API_KEY` (gitignore 대상).
- 모델: Claude Opus 5.5 (`claude-opus-5-5`, effort `low`), 정해진 JSON 형식으로 응답받는 structured outputs 사용.
- 같은 텍스트는 브라우저 캐시에서 재사용합니다. 두 번째 실행부터는 API 호출 없이 몇 초 안에 끝납니다.
- 정책상 응답을 거절하는 경우에 대비해 서버 측 fallback(`fallbacks: "default"`)을 켭니다.
- 이미지 1장당 1회 호출(OCR 텍스트만 전송, 이미지 자체는 보내지 않음). 샘플 기준 6회입니다.

## 구현 현황 (MVP)

실행: `.env.local` 에 `MASKING_ANTHROPIC_API_KEY` 를 넣고 `pnpm dev` → `/datasets` 에서 샘플 불러오기 → `/jobs/new` 에서 실행.

| 화면 | 경로 |
|---|---|
| 데이터셋 (샘플 불러오기, CSV 업로드, 원본 조회) | `/datasets` |
| 새 작업 (컬럼 역할 확인 후 실행) | `/jobs/new` |
| 실행 목록 · 데이터 흐름(에이전트 화면) · 결과 · 개인정보 & 유용성 | `/jobs`, `/jobs/[id]` |
| 페르소나 라이브러리 | `/personas` |

**데이터 흐름 화면:** 10개 단계를 그립니다. 이미지 레인(메인)의 식별 → 생성 에이전트를 강조하고, 나머지 레인은 "목업"으로 표시합니다. 각 카드에 상태, 소요 시간, 진행률, **실행 위치**(Local DB / 브라우저 / OCR + Anthropic API / 목업)를 표시하고, 클릭하면 로그와 "온프렘 제품에서는 어디서 도는지"를 보여줍니다. 화면 문구는 영어/한국어 전환을 지원합니다(사이드바 하단).

샘플 기준 결과 (2026-10-24):
- 이미지 6장 식별·생성 완료, 이미지 정답지 38/38, 유용성 측정 14/14 통과
- 첫 실행 약 30초 (API 6회, 대부분 OCR 시간), 캐시 재실행은 OCR만 다시 수행
- 누출 검사 5건: 목업 텍스트 탐지기가 놓친 주소·가족 이름 (의도된 한계)

| 교체 지점 | MVP 구현 | 파일 |
|---|---|---|
| `DataSource` | zustand + localStorage | `src/lib/store.ts` |
| `PiiDetector` | Anthropic API (Route Handler) | `src/lib/llm/anthropic-detector.ts`, `src/app/api/detect-pii/route.ts` |
| OCR | tesseract.js (브라우저, 언어 데이터는 CDN에서 로드) | `src/lib/pipeline/image.ts` |
| STT | 전사문 컬럼 사용 (목업) | `src/lib/pipeline/run.ts` |
| 텍스트 PII 탐지 | 규칙 기반 목업 탐지기 | `src/lib/pipeline/mock-detector.ts` |
| 이미지 렌더링 | 저장된 영역으로 캔버스에 다시 그림 | `src/components/image-canvas.tsx`, `src/components/agent-panel.tsx` |

알려진 한계:
- OCR이 글자를 잘못 읽으면 엉뚱한 단어가 가려질 수 있습니다 (예: 팔찌의 "ALG"를 "JEN"으로 읽어 이름으로 처리). 덜 가리는 쪽이 아니라 더 가리는 쪽의 오류입니다.
- 오디오 원본 파일 자체는 아직 바꾸지 않습니다. 마스킹된 전사문을 브라우저 TTS로 다시 읽어 주는 방식으로 대체합니다.
- tesseract.js 언어 데이터를 CDN에서 받으므로 MVP는 인터넷 연결이 필요합니다. 온프렘 번들에서는 함께 포함해야 합니다.

## A안으로 전환할 때 할 일

1. `DataSource`: localStorage → 병원 DB 커넥터 (SQL Server·Oracle 등, READ only)
2. `PiiDetector`: Anthropic API → 로컬 LLM (vLLM). 같은 JSON 형식을 유지
3. 업로드 안전장치 제거 (외부 전송이 없어지므로)
4. 오프라인 설치 번들, 라이선스, 업데이트 채널

## 열린 이슈

- **날짜 이동 vs Safe Harbor:** Safe Harbor를 엄격히 따르면 날짜는 연도만 남겨야 합니다. 날짜 이동은 간격을 보존해 학습 가치가 높지만, 별도 전문가 판정(Expert Determination)이 필요할 수 있습니다. 데모에서는 "엄격 모드" 토글로 둘 다 보여줄지 결정 필요.
- **의료진 이름 기본값:** 치환할지 유지할지.
- **localStorage 한도:** 업로드가 커지면 IndexedDB로 바꿔야 할 수 있음. 이미지·오디오 파일은 localStorage에 넣기에 크므로, 샘플은 `public/` 경로로 참조하고 업로드 파일은 IndexedDB에 저장하는 방안 검토.
- **오디오 치환 방식:** 비프음 처리(단순, 확실)와 페르소나 음성 합성(데이터 가치 보존, 구현 복잡) 중 선택.
- **목소리 자체도 식별 정보:** 실제 병원 녹음이라면 화자 음성 변조까지 필요할 수 있음. 샘플은 TTS라 해당 없음.
