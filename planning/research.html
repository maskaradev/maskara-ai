02구현 방법 · OpenAI 로컬 모델

OpenAI가 올해 4월 로컬용 개인정보 탐지 모델을 오픈소스로 공개 → “OpenAI 로컬 모델”은 이것으로 해결.

OpenAI Privacy Filter

Apache 2.0탐지
  • 파라미터 1.5B, 실제 활성 계산 50M → 노트북에서도 동작
  • 8종 탐지: 사람, 주소, 이메일, 전화, URL, 날짜, 계좌, 비밀정보
  • PII-Masking-300k F1 96%
  • 스스로 “익명화·컴플라이언스 인증 도구가 아님”이라고 밝힘 (모델 카드)

gpt-oss-20b / 120b

판단vLLM · Ollama
  • 20b: 메모리 16GB / 120b: 80GB GPU 한 장
  • 애매한 값 판정, “같은 사람인가” 판단 담당
  • 승혁님 DGX Spark(128GB)면 120b도 로컬 구동 가능

파이프라인

  1. 읽기 전용으로 DB 연결connector
  2. 형식이 정해진 값(계좌번호 등)을 먼저 잡음regex + Presidio
  3. 문맥상 개인정보 탐지Privacy Filter
  4. 애매한 값 · 동일 인물 판단gpt-oss
  5. 비밀 키 해시 + Faker로 같은 사람 → 같은 페르소나, 날짜는 사람별 동일 일수만큼 이동HMAC + Faker
  6. 바뀐 결과만 별도 저장소에 적재 (원본은 기관 밖으로 안 나감)masked store
  7. 마스킹본만 받아 과제가 여전히 풀리는지 검증 → 리포트Claude
⚠️ 행사 규칙 대응 — AI 기능은 지급된 Claude 크레딧으로
  • 오늘 데모: 문맥 탐지 · 동일 인물 판단 · 과제 검증 모두 Claude로. 데이터는 합성/공개 데이터.
  • 로컬 모델은 “고객 현장에서는 Privacy Filter + gpt-oss로 교체”라는 아키텍처 슬라이드에만.
  • 코드에는 DETECTOR=claude|local 스위치만 둔다.

04의료에서 RL로 할 수 있는 것

두 갈래. RLMask에 맞는 건 ①번 — 에이전트가 의사·원무과처럼 일하도록 학습/평가.

① 의료 에이전트 과제 RLMask 적합

  • 진단 대화: 여러 턴 문답 → 검사 선택 → 진단. 보상 = 정답 진단 (예: AgentClinic)
  • EHR 업무: 기록 조회, 처방 입력, 결과 확인을 도구로 처리 (예: Stanford MedAgentBench)
  • 약물 대조: 날짜별 처방 비교 → 중복·상호작용 탐지
  • 퇴원 요약 · 의료 코딩: 요약 작성, 청구 코드 부여
  • 사전 승인 · 보험 청구: 미국에서 돈이 가장 많이 걸린 업무

② 치료 결정 최적화 고전 RL

  • 패혈증 수액·승압제 용량, 인슐린 투여량, 인공호흡기 설정을 과거 기록으로 학습
  • 수치 데이터 중심이라 우리 주제와는 거리가 있음

그 밖에 코드 속 비밀번호·API 키, 다국어, 공격적 입력, 문맥 의존 예시로 스트레스 테스트 — 상세는 모델 카드 PDF에만.

스스로 밝힌 한계

  • 익명화·컴플라이언스 인증 아님, 여러 보호 장치 중 하나
  • 주로 영어용 — 한국어 등 비라틴 문자는 성능 저하 가능
  • 흔치 않은 이름, 이니셜, 분야 특유 식별자는 놓칠 수 있음
  • 의료·금융은 사람 검토 + 해당 분야 재평가 권장
  • “너무 많이 가리면 후속 판단에 필요한 맥락이 사라진다”고 직접 경고
  • 출력은 [PRIVATE_PERSON] 같은 태그 — 실감 가명 대체 없음
우리한테 주는 의미

탐지는 Privacy Filter 같은 공개 모델에 맡기고, 그 위에 과제 보존율이라는 새 평가 지표를 얹는다. OpenAI 스스로 과잉 마스킹의 맥락 손실을 인정했다.

06비식별화 후에도 특징이 유지됐는지 어떻게 판단하나

세 층으로 잰다. eval 데이터에서는 맨 위 과제 수준이 핵심.

과제 수준같은 결론이 나오나
  • 정답 보존율: 원본 vs 마스킹본으로 같은 과제를 풀었을 때 정답·보상이 같은 비율
  • 모델 순위 보존: 여러 모델을 원본/마스킹 eval로 채점 → Spearman·Kendall 순위 상관. 1에 가까울수록 “eval 가치 그대로”. eval 판매 회사에 핵심 숫자
  • 점수 차이: 모델별 점수가 원본 대비 몇 %p 바뀌었나
데이터 수준분포·관계 유지
  • 나이·성별·진단명·약 분포 비교 (KS 검정, JS divergence)
  • 항목 간 관계 (예: 당뇨 → 인슐린 처방 상관)
  • 시간 간격: 입원~퇴원 일수, 처방 간격 동일
  • 비개인정보(진단명·수치·약 이름)는 원본과 100% 일치
일관성 수준같은 사람은 같은 사람
  • 같은 원본 인물 → 모든 문서·테이블에서 같은 페르소나
  • “그 환자”, “Mr. Kim” 같은 지칭 연결 유지
반대쪽 저울프라이버시
  • 원본 개인정보 잔존율(유출률), 재식별 위험 — “유용성 최대, 유출 0”을 한 화면에

07우리는 무엇이 되어야 하나

On-prem de-identification for RL eval data.
Remove the PII, keep the task.
RL eval 데이터를 위한 온프렘 비식별화. 개인정보는 지우고, 과제는 살린다.

① 에피소드 일관성

여러 턴·여러 테이블·여러 도구 호출에 걸쳐 같은 사람을 같은 페르소나로 유지.

② 과제 보존 검증

마스킹 후에도 정답과 보상이 그대로인지 수치로 증명 (정답 보존율, 순위 상관).

③ 비공개 eval 벤치마크

결과를 private eval로 묶어 판매. 원본은 기관 밖으로 한 번도 안 나감.

하면 안 되는 말

  • “음성·영상·DICOM 오늘 지원” — 근거 없음
