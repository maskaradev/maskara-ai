# 벤치마크 결과 (2026-10-28 갱신)

`maskara bench`로 낸 숫자다. 다시 내려면 `uv sync --all-extras --all-groups` 후 아래를 실행한다.

```
maskara bench --corpus <corpus> --system <system>
```

출력과 점수는 `runs/`에 남는다(git에는 올리지 않는다). 측정 정의는 `src/maskara/bench/score.py` 상단에 있다.

공개 수치는 외부 코퍼스 세 개를 기준으로 한다. 우리가 만든 linked는 따로 보고한다(설계 문서의 2026-10-26 결정).

## 데이터가 뭉개졌는가 (높을수록 좋다)

- 구별성(distinctness): 서로 다른 사람이 서로 다른 값으로 남는가.
- 일관성(consistency): 같은 사람이 같은 값으로 남는가.

| 시스템 | 구별성 ABCD / Nemotron / TAB | 일관성 ABCD / Nemotron / TAB |
|---|---|---|
| 정답 span을 전부 `[CATEGORY]`로 가림 (완벽한 탐지 + 가림) | 71.2% / 65.6% / 20.4% | 100% / 100% / 99.6% |
| Presidio 가림 | 84.5% / 74.6% / 22.6% | 98.4% / 99.1% / 99.4% |
| Presidio + Faker (mention마다 새 값) | 99.8% / 92.5% / 99.6% | 69.0% / 78.8% / 88.5% |
| Presidio + Faker (문서 안에서 같은 값) | 99.8% / 92.5% / 99.6% | 97.1% / 95.6% / 98.8% |
| **maskara 기본값** | **96.9% / 92.7% / 99.8%** | **98.8% / 97.6% / 99.7%** |

- 탐지가 완벽해도 가림 처리는 사람을 뭉갠다. TAB에서 구별성이 20%다. 판결문에 나오는 여러 사람이 모두 `[PERSON]`이 된다.
- 문서 안에서 같은 값을 쓰는 Faker도 문서를 넘어가면 일관성이 깨진다. linked에서 일관성은 51.6%다.

## 아직 남은 것

- **준식별자는 대부분 남긴다.** 기본 preset(balanced)이 그렇게 설계되어 있다. 준식별자 누출은 Nemotron 54.9%, TAB 35.0%다. 인구통계는 약 88%를 그대로 남긴다. 재식별 위험을 측정하지 않았으므로 이 정책이 맞는지 아직 모른다.
- **초기 공개 비교의 유용성은 대리 지표다.** 구별성과 일관성이 실제 업무 성능을 대신하지 않는다. 기존 QA는 linked에서만 측정했다. 2026-10-27에 추가한 외부 데이터 후속 분류 실험은 아래에 따로 기록하며, 다른 업무·모델까지 일반화하지 않는다.
- **Nemotron의 ID 누출이 12.9%다.** 남은 직접 누출 중 가장 크다.
- **채점 규칙.** 형식 단어(`https`, `com`, `Avenue`)와 mention 앞의 코드(`CUS-`, `1-`)는 남아도 누출로 세지 않는다. 테스트는 `tests/test_score.py`에 있다.

## 2026-10-27: 동일 조건 대체 실험

기존 비교의 `presidio-fake-consistent`는 문서 내부에서만 매핑을 공유했다. 이 비교만으로 문서 간 일관성이나 가상 인물의 추가 이점을 주장하지 않도록 더 강한 비교군을 추가했다.

`maskara bench-replacements`는 탐지와 인물 연결을 **한 번** 실행하고 탐지 위치·연결된 사람·유지 여부를 고정한다. 변경된 이름과 연락처(PERSON, CONTACT) 표현만 바꾸며, 날짜·ID·주소·지역·인구통계·미탐지 구간은 Maskara의 출력을 그대로 공유한다. 특히 토큰 비교군의 날짜를 `[DATE]`로 바꾸어 QA에 불리하게 만들지 않는다. linked에서는 모든 비교군에 같은 표 정보를 제공하고, 외부 세 코퍼스에서는 모두 텍스트만 받는다. 변환은 gold span·entity ID·정답을 읽지 않는다.

| 비교군 | 이름·연락처 선택 방법 |
|---|---|
| `matched-value-faker` | 정규화한 원본값별 Faker 대체. 문서와 호출이 달라도 같은 seed·버전이면 같은 값 |
| `matched-entity-token` | 공통 resolver가 찾은 인물에 고정 토큰 부여. 이름의 전체·이름·성 형태는 구분 |
| `matched-entity-faker` | 동일한 인물 연결 정보를 받은 일반 Faker 이름·연락처. 인물별 이름·성은 함께 생성 |
| `matched-persona` | 같은 실행에서 생성된 Maskara 출력 |

이는 **대체 표현의 효과를 분리하는 실험**이며 독립 제품 네 개를 비교한 결과가 아니다. 인물 연결 오류도 공유한다. 주소·인구통계 정합성의 효과는 이번 실험에 포함하지 않는다. 연락처의 가상 여부·고유성·원본과의 우연한 일치는 Faker가 보장하지 않으며, 발생하면 기존 채점기에 반영된다. 토큰 비율은 표현 방식의 설명이지 낮을수록 좋은 업무 성능 지표가 아니다.

실행마다 `input_sha256`, `plan_sha256`, seed, detector, preset, 버전을 저장한다. 전체 준비 시간은 공통 비용이므로 비교군별 처리 성능인 것처럼 보고하지 않는다. 각 출력과 QA 정답 여부는 지정한 `runs/` 디렉터리에 남는다. 공개 seed는 재현 실험용이며 실제 개인정보 보호용 키로 사용하면 안 된다.

### rules + known: linked 전체 441문서, QA 250문항

| 비교군 | 연결형 QA | 날짜 간격을 포함한 공통 조건 |
|---|---:|---|
| 전역 값 매핑 Faker | 250/250 (100%) | 동일 |
| 인물별 고정 토큰 | 250/250 (100%) | 동일 |
| 인물별 Faker | 250/250 (100%) | 동일 |
| Maskara | 250/250 (100%) | 동일 |

**이 과제에서는 가상 인물의 추가 이점이 관측되지 않았다.** 일관된 매핑과 날짜 처리를 갖춘 비교군도 모두 풀었다. 시험 코퍼스는 자체 생성이고 reader는 gold mention 위치와 대화 소유자 구조를 받는 결정론적 연결기다. 이 100%는 자연어를 스스로 이해하는 LLM 성능도, 개인정보 보호 수준도 아니다. 이후에는 독립 자료의 동명이인·약칭·연락처 소유자·공동 사건과 실제 업무를 평가해야 한다.

### rules + known + GLiNER2: 네 코퍼스의 동일 조건 비교

각 셀은 기존 채점기의 **직접식별자 mention 전체 잔존률**이다. 네 비교군은 같은 탐지 결과를 공유하므로 원본 단어를 우연히 다시 생성하는 경우 등을 제외하면 잔존률도 비슷하다. 이 수치는 재식별 공격 성공률이 아니다.

| 코퍼스 | 전역 값 매핑 Faker | 인물별 고정 토큰 | 인물별 Faker | Maskara |
|---|---:|---:|---:|---:|
| linked (441) | 0.03% | 0.03% | 0.03% | 0.03% |
| ABCD (1,004) | 2.44% | 2.44% | 2.44% | 2.44% |
| Nemotron-PII (1,000) | 4.97% | 4.91% | 5.08% | 4.93% |
| TAB (127) | 37.28% | 37.28% | 37.28% | 37.28% |

GLiNER2 조건에서도 linked QA는 네 비교군 모두 250/250이었다. TAB은 `legal-echr` 팩을 켜지 않은 결과다. 기존의 탐지기별 차이를 가상 인물 대체 자체의 효과와 구분해야 한다.

rules와 GLiNER2의 총 8개 코퍼스·탐지 설정, 32개 변형 점수, 외부 분류 결과, 독립 Presidio 비교군을 [bench-evidence.json](bench-evidence.json)에 집계했다. 입력·공통 처리 계획·저장된 출력의 SHA-256과 버전을 포함한다. 저장된 출력에서 모든 비교군의 edit 위치가 같은지도 검사했다. 학습 원문이나 원본 개인정보 매핑은 이 집계 파일에 포함하지 않는다.

### 독립 비교군: 전역 Presidio + Faker

`presidio-fake-global`을 추가했다. 같은 `(타입, 정규화한 값)`에 대해 seed를 파생하므로 문서 순서와 호출 경계에 관계없이 같은 Faker 값을 낸다. 원본값별 매핑이므로 이름과 약칭을 동일 인물로 해석하는 기능은 없고, 날짜는 인물별 이동 대신 값별 Faker 날짜다. 기존 문서 내부 매핑 비교군도 그대로 유지한다.

| 코퍼스 | 문서 수 | 직접식별자 잔존 | 일관성 | 구별성 |
|---|---:|---:|---:|---:|
| linked | 441 | 11.2% | 94.2% | 97.5% |
| ABCD | 1,004 | 17.9% | 97.2% | 99.8% |
| TAB | 127 | 37.6% | 98.9% | 99.6% |

linked QA는 119/250(47.6%)다. 탐지기·표 정보·날짜 정책도 다르므로 이 격차를 가상 인물 표현 자체의 효과로 해석하지 않는다. 그 효과를 분리하는 비교는 위의 동일 조건 실험이다.

### 외부 후속 작업: ABCD 상담 flow 분류

공식 train 8,034건을 각 방식으로 변환해 분류기를 각각 학습하고, 공식 test 1,004건은 원본 그대로 모든 분류기에 제공했다. 작업은 **상담 전문을 본 뒤 flow를 분류하는 것**이다. 고정된 word unigram/bigram multinomial Naive Bayes(α=1)를 사용하며 어휘·빈도·클래스 사전확률은 train에서만 학습한다. test를 이용한 설정 선택이나 튜닝은 하지 않았다. 원본 학습도 같은 분류기와 test를 사용한다.

| 학습 데이터 | 정답 / 1,004 | 정확도 | Macro-F1 |
|---|---:|---:|---:|
| 원본 | 930 | 92.63% | 92.46% |
| 전역 값 매핑 Faker | 935 | 93.13% | 92.92% |
| 인물별 고정 토큰 | 935 | 93.13% | 92.87% |
| 인물별 Faker | 935 | 93.13% | 92.92% |
| Maskara | 936 | 93.23% | 93.01% |

**Maskara와 강한 비교군 사이의 정확도 차이는 1문항(약 0.10%p)이다.** 단일 seed·모델·작업에서 나온 결과이므로 가상 인물의 우위를 입증한 것으로 보지 않는다. 이 실험은 외부 코퍼스의 실제 학습 후 성능을 측정하지만, 인물 연결 능력이나 LLM 미세조정, 실시간 상담 응답의 품질을 측정하지는 않는다. 개인정보가 작업에 불필요한 상담 분류에서는 다른 대체 방식도 충분할 수 있다.

변환은 **rules 탐지**로 실행했다. 같은 설정의 별도 ABCD test 마스킹 실험에서 직접식별자 잔존률은 27.4%다. 따라서 이 분류 점수를 높은 개인정보 보호 수준에서의 유용성 보존으로 주장할 수 없다. 고재현율 탐지로 전체 train을 변환한 실험, 여러 seed·분류기·업무, 재식별 공격 평가는 후속이다. ABCD는 사람이 역할을 맡아 작성한 대화이며 고객사의 실제 운영 자료는 아니다.

원시 점수·flow별 성능·문서별 예측·원본 학습 대비 wins/losses·입력 fingerprint·패키지 버전은 `runs/utility/rules/abcd--flow-utility.json`에 기록했다. 원본 대비 Maskara는 6건을 더 맞히고 추가로 틀린 건은 0건이었지만, 이것도 해당 고정 test에서의 관측이다.

### 결과에 따른 다음 순서

가상 인물의 자연스러움이나 표·텍스트 동시 처리만을 핵심 우위로 내세우지 않는다. 다음 개발은 **동명이인·약칭·연락처 소유자·공동 사건의 연결 정확도와 보류 처리**, 이어서 **텍스트·테이블 및 반복 반출의 공격 평가**다. 이 결과를 바탕으로 작업별 보존 제약과 위험 기준을 충족하는 정책을 고르는 기능을 설계한다. 사진·음성 확장과 최초성 주장은 그 증거를 대신하지 않는다. 단계별 완료 기준은 [설계 문서](v0-design.md#2026-10-27-후속-계획과-완료-기준)에 있다.

### 재현

```bash
uv sync --all-extras --all-groups
uv run maskara bench-replacements --corpus linked abcd nemotron-pii tab --detector rules --out runs/replacements/rules
uv run maskara bench-replacements --corpus linked abcd nemotron-pii tab --detector gliner2 --out runs/replacements/gliner2
uv run maskara bench --corpus linked abcd tab --system presidio-fake-global --qa linking --out runs/replacements/presidio-global
uv run maskara bench-utility --detector rules --out runs/utility/rules
```

코퍼스별로 결과를 분리하며 `legal-echr` 패턴 팩은 이번 기본 비교에서 사용하지 않는다. 다른 seed·설정으로 실행할 때는 다른 `--out`을 지정해 기존 결과를 보존한다.

## 2026-10-28: 인물 연결 보류와 회귀 평가

복수 후보를 순서로 확정하던 resolver를 수정하고, 표의 이름·이메일 등 소유자 정보가 충돌하는 행은 보류하도록 했다. 표 없는 이름은 문서 내부의 임시 군집으로만 묶으며, `review.json`에 위치·보류 사유·후보 수를 남긴다. `maskara bench-identity`는 gold span을 제공해 탐지와 분리한 소유자 평가를 실행한다.

자체 작성 **32개 사례·48개 mention**에서 근거 없이 확정한 연결은 **20 → 0건**, 확정 연결의 정밀도는 **56.52% → 100%**, 정답 소유자가 있는 mention의 재현율은 **100% → 100%**였다. 보류율은 **4.17% → 45.83%**다. 구현을 겨냥한 진단 사례이며 독립 정답셋이나 고객 데이터 평가가 아니다.

기존 linked 전체에 대해서도 rules+known으로 재실행했다. QA는 **250/250**, 직접식별자 전체 잔존률은 **0.03%**로 유지됐다. 일관성은 **99.45% → 99.15%**, 구별성은 **96.89% → 96.58%**로 소폭 감소했다. 자동 연결을 줄이면서 발생한 손실도 함께 보고한다. 공동 사건 모델과 일반 공지시 해석은 미구현이다.

[구현·사용법·한계](identity-resolution.md), [변경 전후 점수와 해시](identity-evidence.json)에 세부 기록을 남겼다. 위의 2026-10-27 대체·분류 점수는 이전 resolver로 얻은 역사적 실행 결과다. 새로운 resolver로 32개 대체 변형과 전체 ABCD 학습을 다시 실행한 것으로 간주하지 않는다.
